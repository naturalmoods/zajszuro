# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Zajszűrő": a Manifest V3 Chrome extension for news sites. It auto-runs on hirkereso.hu and hirstart.hu; on any other page, clicking the toolbar icon injects it (`chrome.scripting`, activeTab), and clicking again toggles the panel via `window.__kvmToggle`. It picks headlines matching a free-text interest, filters by topic, and scores headlines from 0 (factual) to 100 (heavy clickbait). It's built for the Hungarian market, with no backend: every user brings their own TypeSafe key. Everything user-facing is Hungarian, and so are code comments, the README, `LICENSE.hu.md` (a Hungarian translation of the MIT `LICENSE`, which stays in English so GitHub detects it) and commit messages; this file stays in English. The Jev prompts in `src/scorers.js` are deliberately English, because TypeSafe doesn't claim Hungarian support. Author: Cziczlavicz Péter.

## Development

There's no build step, package.json or linter. It's plain JS loaded as is.

- Site test (no key needed): `node test/sites.mjs https://telex.hu/ ...` opens live pages in headless Chromium over CDP, injects `content.js` with a simulated background, and drives scoring, typing, search, tab switching, clicking panel links and collapse with real input events. Screenshots go to `test/out/`. Prints `OK`/`HIBA` per site.
- Prompt comparison (real API): `TYPESAFE_API_KEY=ts_... node test/compare.mjs` runs the legacy v1 prompts (embedded verbatim) and the current ones on 30 fixed real headlines, and prints real token counts, cost and agreement. Run it before changing prompts.
- Smoke test (real API call, Node 18+): `TYPESAFE_API_KEY=ts_... node test/jev.mjs`. It scores three sample headlines with 1 and 4 questions each, prints both timings, and asserts the factual one scores lowest.
- Load it: `chrome://extensions` → Developer mode → "Load unpacked" → this folder. Then open https://www.hirkereso.hu/ or https://www.hirstart.hu/.
- After an edit, click reload on the extension card, then reload the hirkereso tab.
- Jev (TypeSafe) is the only scorer, and it needs an API key (set it on the options page). Without one, the panel shows an error.

## Architecture

The extension has three contexts. They talk through `chrome.runtime` messaging and `chrome.storage.local`:

- **`src/content.js`** (classic script, **not** a module, so it can't import): `HIRSTART` / `HIRKERESO` / `GENERIC` (hostname) pick the site logic. `GENERIC` uses a heuristic in `titleOf` / `isTitle` / `linkInfo` / `rowOf`: visible link text via `innerText`, outside nav/header/footer/aside, 20–220 chars, mostly letters, not an ad network link (`AD_HOSTS`), capped at `GENERIC_MAX`. `scan()` reads everything first and only then writes badges, to avoid layout thrash from `innerText`. The page shows one view at a time (`ui.view`: body class `kvm-view-pick` or `kvm-view-bait`, scoped in `content.css`), so search/topic dimming and clickbait badges/heatmap never mix. **Panel clicks and keys go through one `window` capture listener (`onClick` routes)**, because some sites (telex) stop click propagation at window capture before it reaches shadow-DOM targets. Don't add `click` listeners on panel elements. List items in the panel are real `<a>` links. A plain click opens the page's link target via a detached anchor, so page scripts can't swallow it (hirstart swallows programmatic clicks on its own links). In `test/sites.mjs` the content script runs in an isolated world, like the real one, so page overrides such as `window.open` don't skew results. The host uses the max z-index, so it sits above consent overlays. `linkInfo()` returns `{id, target}`: on hirkereso it comes from the `rd.hirkereso.hu/rd/<id>?url=` links, on hirstart from direct article links marked `rel="hs_<id>_…"`. Hirstart ids get an `hs` prefix so the cache doesn't mix up the two sites. Links are deduped by id. Hirkereso truncates long titles with "…", so `slugHint()` pulls a hint from the article URL slug. `ROW` picks the row element that heatmap and filter color (`li` on hirkereso, `.rovidhir`/`.boxhir` on hirstart). On hirstart the badge goes *inside* the link, because the link is a line-clamped block. The script draws the badges and a shadow-DOM control panel. `scan()` is used both at load time and by a `MutationObserver`, so headlines added later get badges and are sent as an extra run. The script opens a long-lived port named `kv-score` and sends `{type:"score", run, items, force}`. The first run's items are ordered so on-screen ones go first. Several runs can share the port, and every reply carries `run`: `start` (with labels, concurrency, batch size, `qpc`), `req` (a Jev call started/finished, for the timeline), `results`, `done` / `fatal`. Run kinds are `main`, `more` (late headlines) and `interest`. `interest` is the free-text search, sent as `{type:"interest", run, query, items}`; its results are `{id, match}` and it isn't cached. A superseded search is stopped with `{type:"cancel", run}`. Chrome shuts the MV3 service worker down after ~30 s idle, which disconnects the port. So every send goes through `send()`, which reopens the port via `connect()` when needed; never call `port.postMessage` for a new run directly. `filterRow()` dims rows off the selected topics (`ui.topics`) or below `MATCH` for the search. The panel is a full-height right sidebar (360px). `html.kvm-docked` in `content.css` pushes the page left by the same width, so keep the two in sync. `ui.collapsed` swaps it for a small tab. It has three tabs (`ui.tab`): Válogatás (interest box, topic chips), Kattintásvadászat (display mode, distribution, per-source ranking by the target URL's hostname) and Sebesség (stats, request timeline, re-run). A hover tooltip on each badge shows the per-level probabilities. The Hungarian labels come from `scorers.js` in the `start` message, so they aren't duplicated here.
- **`src/background.js`** (ES module service worker): reads settings, serves cache hits right away, then splits the rest into batches and runs them through a worker pool (`concurrency`). With no API key it sends `fatal` right away. It also owns the selection context menu: `showToast` is injected through `chrome.scripting` (activeTab), so it must stay self-contained. On a 401/403/404/422 it fails all remaining batches instead of sending them. When the port disconnects, an `AbortController` cancels in-flight requests.
- **`src/scorers.js`**: billing is per input token; `state` counts once, every question separately. So the topic/tone/emotion questions are terse, the interest search puts the reader's interest and the `task` once in `state` with a short per-headline `noul`, and `url_hint` is sent only for cut-off titles (`isCut`). The clickbait question (`INSTRUCTION` + `LEVELS`) is deliberately kept in its full v1 wording: compacted variants agreed with v1 on only 73–80% of levels in `test/compare.mjs` (noise floor 97%), the full one on 93%. Don't shorten it without re-running `test/compare.mjs`. `askJev` does the POST to `api.typesafe.ai/v1/systemone`. `scoreWithTypeSafe` sends one `score` question per headline (`h0..hN`) with `LEVELS` as the criteria. When `cfg.extras` is on (the extension always sets it; only `test/jev.mjs` compares with it off), it adds `e{i}` (emotion score), `t{i}` (tone choice) and `c{i}` (topic choice) to the same request. `matchInterest` asks one `noul` per headline (`m{i}`), with the reader's free-text interest as a structured field of the instructions. Both return `{ results, tokens }`: `results` is `[{ id, score 0–100, level 0–4, confidence, probs }]` (or `{ id, match }`), or `{ id, error }` per item; `tokens` is `usage.input_tokens` from the response. Cost is tokens × `USD_PER_MTOK` (TypeSafe price, output is free). The background puts `tokens` on each `req` end message and sends `usdPerMtok` / `usdHuf` (setting) in `start`; the Sebesség tab lists per-call cost in Ft and USD. `fetchWithRetry` handles backoff and `Retry-After`, and builds the Hungarian error hints.
- **`src/settings.js`**: holds `DEFAULTS`, which `background.js` and `options.js` share.

**Cache:** keys have the form `c:${PROMPT_VERSION}x:ts:${model}:${titleKey(title)}` (normalized headline text, not the site id, so the same headline on another site or page is a hit; identical titles within a run are sent once, see `dupes` in `background.js`), where `x` marks results that include the extras, and the value is `{t, r}`, kept in `chrome.storage.local` with a 48h TTL. Stale entries get pruned after each run. If you change `LEVELS`, `INSTRUCTION` or the prompt wording, **bump `PROMPT_VERSION`**. Otherwise old cached scores get mixed in with the new ones.

**Fragility:** scraping depends on each site's link markup and row classes. If a site changes, update `linkInfo()` / `scan()` / `ROW` in `content.js` (on generic pages `titleOf()` / `isTitle()` / `rowOf()`), then check with `test/sites.mjs`. Headless Chromium `--dump-dom` never finishes on hirstart.hu (ads keep the page loading), which is why `test/sites.mjs` drives pages over CDP instead.

The API key is stored unencrypted in `chrome.storage.local`. That's fine for local use, but a publicly distributed build with a shared key would need a backend proxy.
